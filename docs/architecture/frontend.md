# Frontend (`frontend/src`)

- `api/client.ts` wraps `fetch` with `credentials: "include"` and throws an `ApiError` (`api/errors.ts`) whose message is the error code's Turkish text (`ERROR_TEXT`, a `Record<ErrorCode, string>`, so a code without its text fails the typecheck; `errors.test.ts` checks `ERROR_CODES` against the backend's `ErrorCode`). A 401 from anything but `/api/me` tells `AuthContext` (`onUnauthenticated`), which shows the page signed out with "Oturumun sona erdi" (`components/AuthNotice.tsx`, which also shows `?login_error=`). `api/types.ts` mirrors the Rust response structs by hand, so update it whenever a serialized struct changes.
- `auth/AuthContext.tsx` loads `/api/me` on startup. `RequireAuth access=…` guards routes (a role, which hosts always pass, or `"staff"` for any role); `/admin/*` needs any staff role but Graphics Designer and Commentator, `/admin/bracket` the `"matches"` roles, `/admin/qualifiers` and `/admin/referee/:matchId` need referee, `/admin/mappool` needs `"pool"` (editing needs map_pooler) and `/admin/stages|users|teams|rules|discord|bancho` need host. Stages are created, renamed, reordered and deleted on `/admin/stages` (`pages/admin/StagesAdminPage.tsx`); the map pool editor only picks, publishes and fills them. Admin tabs are listed with who can open them in `lib/adminTabs.ts`. A page's changes go through `lib/useAction.ts` (busy, the error, and a reload after). On `/admin/*` the top bar (`components/NavBar.tsx`) swaps the public links for those tabs, turns a tinted colour (`--color-admin-*` in `tokens.css`) with a "Yönetim panelindesin" label in the middle, and its right-hand "Yönetim" button becomes "Siteye dön", which goes back to the last public page. Coming back, `/admin` (`AdminIndexRedirect`) reopens the last admin page the user was on, with its query and including a referee room, as long as their role still allows it (saved per user in localStorage).
- The map pool editor lives in `pages/admin/mappool/`. `useStageEditor.ts` owns all of its data and API calls, and the `.tsx` files only render. Structural changes go through `run()`, which shows a busy state and then reloads the stage. Small edits (notes, colours, ordering) update local state first and save in the background.
- The bracket views live in `components/bracket/`: `BracketGrid` (cards on a board with SVG lines for winner/loser links, shown in a fixed frame that pans and zooms with a CSS transform rather than scrolling: drag empty space to pan, wheel/pinch/buttons to zoom, recenter fits every match; when editable, pointer dragging snaps to board units, cards can't overlap, arrow keys nudge and double-click adds; the overlap rule lives only in the frontend, `overlapsAny` in `lib/bracket.ts`), `BracketList` and `BracketCalendar`, shared by the public `/bracket` page and `pages/admin/bracket/`. The search in the page header (`BracketSearch.tsx`) is shared by all three: the list and the calendar only show the matches it finds, the grid dims the rest so the board keeps its layout. There, `useBracketEditor.ts` owns the data and API calls (moves update locally and save after a short debounce) and `MatchPanel.tsx` edits the selected match. Its referee and streamer controls (`StaffControls.tsx`: a select for hosts, take/give up buttons for everyone else) are also in the list view's rows, so those can be changed without opening the panel.
- Every `TeamCard` (the teams pages and the `TeamPopover` used by the bracket and qualifier views) has a "Maçlar" button that blurs the card and lays the team's next bracket match and match history over it (`components/TeamMatches.tsx`, built from `/api/public/bracket`); `/team` turns it off and shows `TeamMatches` in its own section instead. `/teams` and `/admin/teams` can also show the teams as rows (`components/TeamRow.tsx`: `TeamRows` lines the rows' columns up with a subgrid; by its own width it drops the banner, moves the row's actions into its panel and turns "Maçlar" into a bare chevron under 1000px, and turns each team into two lines under 560px; "Maçlar" opens `TeamMatches` under the row), switched by `TeamViewTabs` ("Kartlar" / "Satırlar", remembered per browser by `useTeamView`; phones start on rows); the admin page builds both from one `teamProps`. Each match links to `bracketMatchPath` (`/bracket?match=<id>`, or `/admin/bracket` from an admin page), which both bracket pages read with `useLinkedMatch`: it switches to the grid, selects the match, centres on it (`BracketGrid`'s `centerOn`) and drops the parameter.
- `player/PlayerContext.tsx` and `components/MiniPlayer.tsx` provide an app-wide song preview player.

Frontend conventions (from `frontend/README.md`):
- Each component keeps its CSS next to it (`MapCard.tsx` + `MapCard.css`). Colours, spacing and font sizes come from the variables in `styles/tokens.css`.
- Icon-only buttons use `<IconButton label="…">`; new icons go in the `ICONS` map in `components/Icon.tsx`.
- Anything done by dragging also needs a button/select alternative (e.g. "Move to…" on map cards).
- The staff pages and the heavier public ones (match page, statistics, pick'em) are `lazy()` in `App.tsx`, under a `Suspense` around the routes (and one around `AdminLayout`'s `Outlet`, so the admin tabs stay while one loads). `components/ErrorBoundary.tsx` keeps a render error from blanking the app: around `<main>` and the referee page (a "Yeniden yükle" message), and around the overlay (nothing, so the stream stays clean, and it draws again after 5 s); each is keyed by the path.
- `npm run lint` is ESLint (`eslint.config.js`) with the rules of hooks and `exhaustive-deps`; tsc already reports unused code. CI (`.github/workflows/ci.yml`) runs it with the typecheck and the tests, and the backend's fmt, clippy (`-D warnings`) and tests.
