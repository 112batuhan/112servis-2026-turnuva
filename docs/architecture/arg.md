# ARG (`handlers/arg.rs`, `db/arg.rs`; routes under `/api/kupa`)

- A 72px spot on the snowflake in the landing page's banner (`.landing-hero-link`) links to the hidden `/kupa` (`pages/ArgPage.tsx`), with nothing to show it's a link. Signed-in players with a linked Discord type answers there: three secret messages, entered in any order (each guess is checked against all three), each answered by its reply; the first to enter the third wins. The answers and replies are only in the environment (`ArgConfig` in `config.rs`: `ARG_ANSWER_1..3`, `ARG_REPLY_1..3`; off, 404, unless all six are set), and only the server checks them (ignoring case, spacing and İ/I/ı/i), so the frontend must never carry an answer or a reply: a message's reply is only sent in answer to the guess that entered it (`POST /api/kupa`, the only call the page makes; it shows the latest guess's reply alone), and entering a message again sends it again. A reply's `{place}` becomes their place among that message's finders. `arg_solves` (one row per player per message, `id` the order; the first to enter message 3 wins) and `arg_attempts` (every guess with the message it matched, null when wrong; 10 per 10 minutes per player) hold the progress. `GET /api/kupa/results/<ARG_RESULTS_TOKEN>` is a server-rendered HTML page for the hosts (escaped, `no-store`, 404 without the token): the winner, how many found each message and who first, each message's finders in order, every player with which messages they entered (place and time), the latest wrong guesses, and a "Denemeleri sıfırla" button (`POST` to the same URL, confirmed in the browser) that deletes every attempt and solve.
